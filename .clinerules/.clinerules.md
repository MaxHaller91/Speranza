# Speranza — Cline Instructions

## START OF EVERY SESSION: Read These Files First
Before doing ANYTHING else — before reading code, before planning, before asking questions — read these files in order: Try using subagents when possible. 

1. `memory-bank/activeContext.md` — what's happening right now
2. `memory-bank/progress.md` — what works and what doesn't
3. `memory-bank/systemPatterns.md` — how the architecture works
4. `.clinerules/01-architecture.md` — where everything lives
5. `.clinerules/03-speranza-domain.md` — game mechanics knowledge

Only read the others if the task requires them.

## The One Rule That Overrides Everything
**Read the file before you edit it.**
No exceptions. Even if you think you know what's in it. Even for a one-line change.

## Skill Creation Radar
After solving any non-trivial problem, ask yourself: "Would I have to figure this out again 
from scratch next time?" If yes, suggest to the user: "This could be a good skill — want me 
to capture it in a SKILL.md?" Then offer to write it immediately while the context is fresh.

Patterns worth capturing:
- Multi-step processes with a specific order that matters
- Bugs that required understanding a non-obvious root cause
- Any time you had to read 3+ files to understand where to make a change
- Anything where getting it wrong would break working systems

## END OF EVERY SESSION — Mandatory
Before closing out any session, whether the task is done or mid-flight:

Update memory-bank/activeContext.md — current state, what's in progress, what's broken
Update memory-bank/progress.md — what changed this session
Log any new architectural decisions to memory-bank/systemPatterns.md
Run a syntax/lint check on every file that was edited this session

Do not skip this even if the task felt small. Do not skip this if you're low on context.
If context is running low, prioritize the memory update over finishing the task.

### When to Update the Memory Bank
Update `memory-bank/activeContext.md` and `memory-bank/progress.md` when:
- A significant feature is completed
- A bug is found and fixed
- An architectural decision is made
- The session is ending and work is mid-flight

You can update these files yourself — they're just markdown.

## Plan Mode vs Act Mode
These rules govern how Cline behaves regardless of which mode you've set:

**Before writing any code that touches more than one file OR any system 
flagged as risky in systemPatterns.md:**
1. Write out your plan in plain text — what files, what changes, in what order
2. State the single riskiest part of the change
3. Stop and wait for explicit approval before touching any code

**For simple, clearly contained tasks (single file, known location):**
- State what you're going to do in one sentence
- Proceed without waiting for approval

The rule of thumb: if you're uncertain where the code lives, stop and plan first.

Use **Act mode** when:
- The task is clear and contained (single file, known location)
- You've already planned and just need to execute

## Quick Reference — Most Common Tasks

**Add a new room type:**
→ Edit `gameData.js`, add entry to ROOM_TYPES with all required fields (bg, border, color, icon, label, desc, cap, produces, consumes, cost). Add sprite if available.

**Add a new handler:**
→ Edit `Speranza.jsx`, find a similar handler, add yours after it. Make sure to pass it as a prop to the relevant component.

**Fix something in the grid:**
→ Edit `src/components/ColonyGrid.jsx`. Props come in from Speranza.jsx — don't add state here.

**Fix something in the side panel:**
→ Edit `src/components/SidePanel.jsx`. This is the largest component — read it carefully first.

**Add a sound:**
→ Add the function to `sounds.js`, import it in Speranza.jsx at the top, call it from the appropriate handler.

**Fix a stale closure bug in the tick loop:**
→ Add a ref mirror for the state variable. Sync it in a bare useEffect. Read from the ref inside the loop.
