### Phase 3 — Extract game systems (Plan B, future)
*Only do this once Phase 2 is stable and you feel the tick loop is limiting you.*

At that point Speranza.jsx will be ~1,700 lines of pure game brain. The tick loop sections will be clearly readable and separable:

```
src/
  systems/
    resourceSystem.js   ← production, consumption, net flow calc (~150 lines)
    raidSystem.js       ← heat, raid windows, strikes, T3 defenses (~350 lines)
    expeditionSystem.js ← roll tables, outcomes, loot (~125 lines)
    colonistSystem.js   ← healing, XP, leveling, morale collapse (~200 lines)
    excavationSystem.js ← excavation countdown, row unlocks (~50 lines)
```

Each system would be a pure function: `(state, refs) → stateUpdates`. Speranza.jsx becomes a ~400 line coordinator that runs systems in order each tick.

### Execution rules for all phases
1. **One component at a time** — extract, test in browser, confirm working before the next
2. **No game features during refactor** — don't mix the two
3. **Speranza.jsx stays runnable at every step** — never leave it in a broken intermediate state
4. **Phase 3 is optional** — Phase 2 alone gets you 80% of the practical benefit
